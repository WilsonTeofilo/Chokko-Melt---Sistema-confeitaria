1. O que é um banco de dados (do jeito mais simples)

Imagine uma planilha que salva informações de verdade: clientes, produtos, pedidos. Só que, em vez de uma planilha gigante e bagunçada, a gente divide em várias tabelas menores, cada uma com um assunto.

Por quê? Porque assim não repete o mesmo dado dez vezes, não mistura “cadastro de pessoa” com “linha de compra”, e o sistema continua rápido e organizado quando crescer.

Cada tabela tem:

  • Linhas = cada registro (ex.: um cliente, um produto).
  • Colunas = os campos (ex.: nome, e-mail, preço).

2. Palavras que você vai ver em todo lugar

TermoO que significa
TabelaUma “folha” com um tema (ex.: cliente guarda só dados de cliente).
Chave primária (PK)Identificador único da linha. Ex.: id_cliente. Nunca se repete dentro daquela tabela.
Chave estrangeira (FK)Uma coluna que aponta para a PK de outra tabela. Ex.: pedido guarda id_cliente para dizer “este pedido é deste cliente”.
Integridade referencialO banco garante que você não associe um pedido a um cliente que não existe. É o papel das FK.
Relacionamento 1:NUm cliente tem vários endereços; cada endereço pertence a um cliente.
Relacionamento N:NMuitos produtos podem ter muitos adicionais. A tabela no meio (produto_adicional) resolve isso.
ENUMLista fixa de valores permitidos (ex.: formas de pagamento). Ajuda a evitar erro de digitação.

3. Por que o modelo é assim (ideia geral do Chokko Melt)

O sistema vende doces pela internet/local. Precisa guardar:

  • Quem vende/controla: usuario (admin/funcionário).
  • Quem compra: cliente (com login normal ou Google).
  • Onde entregar: endereco.
  • O que vende: categoria, produto, opcionalmente adicional.
  • Carrinho antes de fechar compra: carrinho, item_carrinho, item_carrinho_adicional.
  • Pedido fechado: pedido, item_pedido, item_pedido_adicional, status_pedido.
  • Pagamento (sem gateway online obrigatório): pagamento, status_pagamento (+ troco em dinheiro).
  • Regras da loja: config_loja (horário, WhatsApp opcional).
  • Satisfação: avaliacao ligada ao pedido.

6. Um pedido do início ao fim (passo a passo mental)

  1. O cliente navega pelos produtos (e categorias). Se marcar extras, isso vira linhas no carrinho e item_carrinho_adicional.
  2. Ao finalizar, o sistema cria um pedido com id_status_pedido = PENDENTE (ou o que sua regra definir), copia itens para item_pedido e extras para item_pedido_adicional (com snapshot).
  3. Cria-se pagamento com forma (PIX, cartão, dinheiro) e, se dinheiro, preenche valor_entregue e troco.
  4. O painel muda status_pedido (aceito, preparo, enviado, entregue) conforme a operação.
  5. Se cancelar, preenche motivo_cancelamento, cancelado_por, cancelado_em e o status adequado na tabela de status.
  6. Depois de entregue, o cliente pode deixar uma avaliacao ligada ao pedido.
